# Mobile read-only PWA cloud preview

The Account screen offers an explicit preview action to verified signed-in users. Opening the modal, restoring an auth session, signing in, and reconnecting do not fetch the cloud library. The preview reads the account document and, when applicable, only the active ordinary library page collection under `users/{uid}/libraries/{revision}/pages`. It does not query the PWA's `privateNotes` or `privateNoteVersions` collections.

For a completed PWA schema-v3 account, Mobile requires `syncVersion: 3`, `privateNotesSchemaRequired: true`, and `privateNotesSeparated: true` before reading pages. If the compatibility fence exists but separation is incomplete or inconsistent, preview stops before reading pages. In v3 ordinary pages, a note marked private or carrying an ambiguous privacy marker blocks the preview. The known PWA importer shape `isPrivate: false` plus `privateData: null` is accepted as ordinary only in v3, and neither marker is projected into the preview.

Older root snapshots and paged schema-v2 libraries can still contain mixed records. For those legacy sources, Mobile excludes any note with a `privateData` property or a truthy `isPrivate` flag before enumerating or projecting its fields. The preview never displays or decrypts private payloads. It projects only Mobile-supported note fields; unsupported PWA field names (including attachment descriptors) may be listed, but their values, paths, URLs, and files are not read.

This is a preview only: it does not synchronize in either direction, import or merge cloud data, or write to Firestore. It does not modify device notes, drafts, folders, Private Notes, attachments, or deletion markers. A failed or incomplete read is shown as an error, never as an empty library. Automated tests use mocked reads and make no production Firebase connections; production rules and read behavior have not been independently verified here.
